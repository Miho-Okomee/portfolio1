この学習ロードマップでの Claude Design 活用イメージ

Phase 1 Material Design などの既存DSをClaude Designに読み込み、どう解釈するか見て学ぶ。基礎の理解が直感的になる
Phase 2 Atomic Designを学びながら、実際にClaude Designでコンポーネントを試作。設計思想と出力結果を比較する
Phase 3 エクスポート機能（HTML / PPTX）を使い、Storybookと比較。ツールの使い分けを体感しながらトークン設計を深める
Phase 4 このポートフォリオにClaude Designで作ったモックアップを適用 → Claude Code に引き継いで実装。ワークフロー全体を体験する
⚠️ 現時点の制限（研究プレビュー段階）
  • インラインコメントが消失する場合がある
  • 大規模なコードベース読み込み時にラグが生じることがある
  • 細かなレイアウト調整はFigmaには及ばない（プロトタイプ初期段階として活用するのが現実的）

Claude Design 会話フレーズ集

精度・確度を上げるために、セクション別に使い分ける

チャット大きな変更・構造変更向き インライン細部の局所修正向き DS設定デザインシステム構築時 出力エクスポート・引き継ぎ
🎛
① モード・全体方針の指定
最初にモードを宣言すると精度が上がる
チャット「プロトタイプモードで、UIのワイヤーフレームを作って」
グレースケールの構造図として生成される。最初に形を決めてから色をつける流れが精度◎
チャット「スライドモードで、5枚構成のピッチデッキを作って。構成：課題 / 解決策 / 市場 / チーム / 次のステップ」
スライド枚数と構成を最初に渡すと骨格がぶれない
チャット「現在の状態を保存して、別アプローチで2バリアント作って」
バージョン管理機能を活用。比較しながら方向性を決める使い方が精度を上げる近道
🎨
② スタイル・トーンの語彙
「なんとなく良い感じ」を具体的な言葉に変換する
ミニマル・洗練
「余白を広めに、テキストは細めのウェイト（font-weight: 300）、装飾は最小限で」
コーポレート・信頼感
「ネイビー・ホワイト基調、直線的なレイアウト、余白は控えめ、グリッドを厳格に守って」
カジュアル・フレンドリー
「丸みのあるコーナー（border-radius: 12px〜）、暖色系アクセント、アイコンを多用して」
高級感・プレミアム
「ダークバックグラウンド、ゴールドのアクセント、セリフ体の見出し、余白を最大限広く」
📐
③ レイアウト・構造の指示
セクション名と配置を明示すると解釈ズレが減る
チャット「ページ構成：ヒーロー → 特徴3列 → お客様の声 → CTA → フッター」
セクション順を最初に宣言するだけで大幅にズレが減る。最重要テクニック
チャット「CTAボタンをfold（スクロールなしで見える範囲）内に配置して」
fold はWebデザイン用語。ファーストビューにCTAを置く指示として通じる
チャット「ヒーローセクションを左テキスト・右画像の2カラム、画像は aspect-ratio: 4/3 で」
比率まで指定すると画像プレースホルダーの形がぶれない
インライン「このセクション全体の上下パディングを120pxにして」
px値を明示すると、曖昧な「余白を増やして」より確実に意図が伝わる
🖋
④ タイポグラフィ・色の指定
数値で渡すと解釈ズレがゼロになる
DS設定「タイポグラフィスケール：H1=48px/300、H2=32px/400、本文=16px/400、キャプション=13px/400」
サイズと font-weight をセットで渡すのが◎。デザインシステム設定時に一度決めてしまう
DS設定「カラーパレット：プライマリ #C9A961、テキスト #2C2C2C、背景 #FAFAF8、グレー #6B6B6B」
HEXコードで渡せば色のブレが完全になくなる。このポートフォリオのCSSから転用してみよう
インライン「このCTAボタンの背景を #C9A961、テキストを #FFFFFF、hover時は透明背景＋ #C9A961 のborderで」
ホバー状態まで指定すると実装前提のデザインとして整合性が上がる
🧩
⑤ コンポーネント・状態の指示
状態（state）を明示すると実装者への伝達精度が上がる
チャット「Buttonコンポーネントを3バリアントで：Primary（塗り）/ Secondary（ボーダーのみ）/ Ghost（テキストのみ）」
Atomic Design の Atoms レベルで語彙を合わせておくと、Phase 2以降の学習と接続しやすい
インライン「このFormFieldの状態を4つ並べて：default / focus / error / disabled」
state（状態）を見える化しておくと、Storybookへの移行（Phase 3）がそのままスムーズになる
チャット「モバイル（375px）とデスクトップ（1280px）の両ブレークポイントを並べて比較できるように表示して」
レスポンシブ設計を確認する定番の指示。ブレークポイント値を明示するのがコツ
📥
⑥ デザインシステム継承の指示
何を読み込ませるかで出力品質が大きく変わる
DS設定「このスクリーンショットからブランドカラーとフォントを抽出して、デザインシステムとして設定して」
既存サイトのキャプチャを貼るだけでDS継承が始まる。最速のセットアップ方法
DS設定「index.html の CSS変数（:root ブロック）を参照して、同じデザイントークンを使って」
このポートフォリオで実践できる。コードを貼り付けてトークンを共有する
DS設定「スペーシングルール：4の倍数（4/8/16/24/32/48/80px）で統一して」
スペーシングシステムを最初に宣言しておくと、余白の指示がすべて一貫する
🔄
⑦ 反復・バージョン管理の指示
「保存 → 試す」のループが品質を上げる
チャット「今の状態を v1 として保存して。次にヒーローの背景を動画にした v2 も作って」
バージョン名を付けると会話の中で「v1 に戻して」と参照できる
チャット「全体の方向性をミニマルからリッチ・プレミアムに変更して。トークンを引き継いだまま雰囲気だけ変えて」
「トークンを引き継いだまま」という条件を付けることで、カラーを壊さずにスタイルだけ変えられる
チャット「ダークモードバージョンを作って。light/dark の2画面を並べて比較表示して」
ダークモード対応はPhase 2の学習トピック。Claude Designで実験すると理解が早い
⚙️
⑧ エクスポート ＆ Claude Code 引き継ぎ
デザインを実装につなげるための指示
出力「スタンドアロンHTMLでエクスポートして。CSSはインラインで埋め込んで」
外部依存なしの1ファイルHTMLが出力される。そのままブラウザで確認 or Claude Codeに渡す
出力「このデザインをClaude Codeに引き継ぐためのコマンドをコピーして」
コマンドをClaude Codeに貼るだけで実装フェーズへ移行。デザイン→コードの手戻りがなくなる
出力「このデザインを実装するために必要なCSSカスタムプロパティ（変数）の一覧を出して」
トークンリストを先に出力させておくと、Storybook（Phase 3）やCSSファイルへの転記がそのまま使える

BEST PRACTICE 精度を最大化する「指示の組み合わせパターン」

LP制作の鉄板スターター
「LPを作って。
 ターゲット：30代ビジネスパーソン
 構成：ヒーロー→特徴3列→CTA
 スタイル：ミニマル、余白広め
 カラー：#C9A961 をプライマリに
 fold内にCTAボタンを配置して」
コンポーネント設計の鉄板スターター
「Buttonコンポーネントを設計して。
 バリアント：Primary / Secondary / Ghost
 状態：default / hover / disabled
 サイズ：sm / md / lg
 カラートークン：#C9A961
 3×3のグリッドで並べて比較表示して」

2時間/日を効果的に使うコツ

1
最初の30分はインプット（読む・見る）、残り90分は手を動かす。読むだけでは身につかない。
2
このポートフォリオのCSSを改善しながら学ぶ。既にCSS変数が使われているので、実践しやすい。
3
Material Design などの実際のDSを「写経」する。なぜそのトークン値にしたか考えながら。
4
週末は振り返りと整理の時間に。ノートやFigmaでその週の学びをまとめることで定着する。
